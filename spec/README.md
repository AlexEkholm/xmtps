# XMTPS file format specifications

This folder specifies every kind of file that XMTPS consumes or produces. That covers the decoder daemon (`src/`), and the Python tools that turn its listings into JSON, plots and web pages (`bin/py/`). Each specification is written from the source code. It is checked against production files on argus, and records any disagreement in its last section.

## Data flow

```
Iridium gateway ──e-mail──▶ stage 1/2 ──▶ RAW, SBD files, MySQL
                                │
       configuration, .meta ───▶│ stage 3 ──▶ listing, PHY files ──▶ xmtps-list2json.py ──▶ per-dive JSON
                                │                                                              │
                                └ stage 4 ──▶ KML, status files          xmtps-aggregate-json.py ◀┘
                                                                              │   ▲ ETOPO bathymetry
                                                aggregate/summary JSON, plots ◀┘
                                                             │
                                  summary, mission and startup page generators ──▶ HTML pages
```

## Specifications

### Consumed by the decoder

| File | Specification | Written by |
|---|---|---|
| Iridium SBD notification e-mail (IMAP, or mail files in `dir.mail`) | [iridium-mail-format.md](iridium-mail-format.md) | Iridium gateway |
| SBD attachment: X-message packets | [xmessage-format.md](xmessage-format.md), also as [text](xmessage-format.txt), [JSON](xmessage-format.json), [YAML](xmessage-format.yaml) and [PDF](xmessage-format.pdf) (generated by `build-formats.py`) | float firmware |
| Configuration file (`-c`, `options.cfg`) | [configuration-file-format.md](configuration-file-format.md) | operator |
| Float metadata (`<DAC-ID>_<serial>.meta`) | [float-metadata-format.md](float-metadata-format.md) | operator |
| MySQL database (read at startup and when reprocessing) | [database-schema.md](database-schema.md) | decoder |

### Produced by the decoder

| File | Specification | Read by |
|---|---|---|
| RAW mail message files (`raw<serial>-<MOMSN>-<dive>-<packet>.txt`) | [raw-file-format.md](raw-file-format.md) | people |
| Binary SBD files (`<serial>-<MOMSN>-<dive>.sbd`) | [sbd-file-format.md](sbd-file-format.md) | people, other decoders |
| Intermediate listing files (`lis<serial>-<dive>.txt`) | [listing-file-format.md](listing-file-format.md) | `xmtps-list2json.py`, people |
| PHY listing files (off by default; none written in production since 2021) | [phy-file-format.md](phy-file-format.md) | `upload-phy.sh` on argus (AOML FTP) |
| KML/KMZ files, per float and master | [kml-file-format.md](kml-file-format.md) | Google Earth |
| Per-float status summaries (`stat<serial>.txt`) | [status-file-format.md](status-file-format.md) | people |
| MySQL database | [database-schema.md](database-schema.md) | decoder |
| Log files, the PID lock file and the `.lck`/`.err` mail input files | [log-and-lock-files.md](log-and-lock-files.md) | people |

### Produced and consumed by the Python tools

| File | Specification |
|---|---|
| Per-dive, aggregate and summary JSON, `.lastprocessed` | [json-file-format.md](json-file-format.md) |
| Plots, float pages, summary, mission and startup pages; the bathymetry and other non-JSON inputs | [plot-and-page-files.md](plot-and-page-files.md) |

Some directories under `/data1/alamo/data` on argus were not written by the current XMTPS. `kkyy/` holds TESAC KKYY files, made by `alamo-upload-kkyy.sh` from the listings (2017–2018). `mat/` holds MATLAB files from the scripts in `/data1/alamo/matlab` (2017–2021). `netcdf/` holds NetCDF files from older XMTPS builds, whose NetCDF writer is now disabled (2019–2021). `plots/` holds the old plot pages, replaced by `plots2/`.

## Known issues

Each specification ends with a section of open questions and discrepancies. These are the places where the code, the README and production files disagree, and some of them are bugs. Fixing such a bug changes the format, so the specification must be updated in the same change.

## Conventions

- Times are UTC. The decoder writes them as ISO 8601 (`2026-10-25T12:03:07Z`) and the binary messages as seconds since 2000-01-01, unless a specification says otherwise.
- IMEIs in the examples are masked to their last seven digits, as the listing files do. Examples never include credentials.
- Statements not taken from the code, but inferred from production data, are marked [inferred].
- The examples in [`../example/`](../example/) are real files from one dive, float 9303 dive 440. They show the mail, SBD, RAW, listing, JSON and plot formats side by side.
